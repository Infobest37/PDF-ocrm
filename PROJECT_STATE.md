## Ловушки, уже проверенные на практике

- Долгие процессы агента (emb-index и др.) умирают вместе с консолью сессии, финальный лог теряется из-за буферизации — о прогрессе судить по данным, а не по логу.
- Прогресс индексации мерить числом записей (`pages_without_vectors`, read-only SQL), не размером файла базы.
- Константы в tests/test_golden_metrics.py должны соответствовать числу вопросов (сейчас 45: 16 explain / 11 fault / 18 procedure); правка набора без правки констант — красный тест.
- Абляционные негативы (скрытие эталонного листа) на этой документации не работают: система отвечает с соседних листов, машинная проверка цитат проходит (0 жёстких негативов из 28). Отказ калибруется только на полигоне Ф1.3а/Ф1.3б; единственный разделяющий сигнал — конкретика вопроса на листе-лидере.
- Метрика отказа двусоставная: сводный refusal_false смешивает ложные и обязательные отказы — контроль ложных ведётся по refusal_false_on_found (требование 0.00), доля обязательных — refusal_on_miss.
- `_print_text` в CLI читает store (`is_continuation`): печать — до `store.close()`, иначе ProgrammingError на ответе с парой соседних листов (исправлено в Ф1.3б.2, закреплено тестами test_graph_cli.py).
- Перезапуск `emb-index` безопасен: ветка continuation пропускает уже закодированное.
- `min_score = 0.35` бессмыслен: лидер OR-ветки всегда 0.8, отказ не сработает никогда.
- Слово SAFIR нельзя фильтровать — это название ВСУ.
- Штампы doclib есть и на полезных листах — автофильтр по штампу отсеял бы 4194 листа.
- Документа РЭ1 от 17.09.2024 в базе нет — есть только 05.03.2026.
- В PowerShell `git show --output=` даёт пустой файл — захват вывода git через Python subprocess; всегда `git --no-pager`.
- Файлы проекта UTF-8, консоль Windows может показывать кириллицу как cp866 — искажённое отображение не повреждение.
