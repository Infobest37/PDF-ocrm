## Данные и индексация

- Абляционные негативы (скрытие эталонного листа пометкой `needs_rescan`) на этой документации непригодны: информация дублируется между изданиями и картами, после скрытия система отвечает с соседних листов, машинная проверка цитат проходит. 0 жёстких негативов из 28. Отказ калибруется только на внешних вопросах и мутациях.
- Прогресс индексации мерить числом записей (`SELECT COUNT(*) … pages_without_vectors`), не размером `graph.db`: WAL колеблется, размер врёт.
- Долгие процессы (`emb-index`) умирают вместе с консолью сессии; финальный лог теряется из-за буферизации — о завершении судить по данным, а не по выводу.
- Перезапуск `emb-index` безопасен: ветка continuation пропускает уже закодированное; повторный запуск идемпотентен.
- Чекпойнты Cline захватывают untracked-файлы в обход `.gitignore` и раздувают `.git` (было 647 МБ на бэкапах по 228 МБ). Держать чекпойнты выключенными, тяжёлые данные — вне папки репозитория.
- `docs/quality-candidates-*.csv`, `reports/` — артефакты вне git; `reports/` в `.gitignore`.
- После чистки поискового текста (`reindex-text`) обязательно пересчитать векторы
  (`emb-index`). Лексический индекс и эмбеддинги строятся из разных копий текста:
  если почистить только один, лексика ищет по чистому, а семантика — по грязному
  («кгс/см?», «ннннннн»), и они расходятся. Признак: лист с явным совпадением слов
  стоит в векторной выдаче на 100+ месте.
- Чанковый канал (Ф1.23а, `chunks_fts`) не поднимает плотные таблицы в RRF:
  голоса распределяются тем же лидерам. Замер 09.11.2026: hit@5 0.645 без
  изменений (состав: +e02, +e14; −e06, −e10), doc_hit@5 упал 0.968→0.871,
  эталонные позиции всех 14 промахов не сдвинулись (e34/e35 — «нет до 50»).
  Плотная таблица листа 38 действительно даёт чанку больший вес BM25, но
  третий голос в RRF достаётся тем же листам-лидерам. Канал оставлен за
  флагом `PDFGRAPH_CHUNK_CHANNEL`, по умолчанию выключен; после `build`/
  `reindex-text` нужен `chunk-index`.

## Поиск и отказ

- `min_score = 0.35` бессмыслен: лидер OR-ветки всегда 0.8, порог не сработает никогда. Отказ строится на гейтах по конкретике.
- Косинусы не разделяют корпусные и внекорпусные: 0.80–0.91 против до 0.817. Порог по близости невозможен, `MIN_COSINE = 0.18` ничего не отсекает.
- Гейты проверяют только лист-лидер. При смене порядка (например, после веса Ф1.5) защита исчезает — так потерян отказ на e04. Кандидат: проверять топ-3.
- Редкий термин (`rare_term`, df<1000) как гейт непригоден: задевает 17 из 23 корпусных.
- Вес specificity сравнивает конкретику по вхождению в текст: выдуманное число может случайно совпасть (400, 20 и т. п.), уточнение срывается в ответ. Clarify-полигон: было 10/10, стало 4/10.
- Роль документа в выдаче карт (Ф1.9б: «manual»/«reglament») определяется по имени файла (`document_role` в `pdfgraph/query.py`): имена плавают — издание, изм., опечатки в имени меняют роль. `documents.family` хранит семейство ВС («Ми-8»), не роль; перевести роль в поле таблицы documents — отдельная задача, сейчас схема не меняется.
- Мерж каналов был продублирован: `query.hybrid_search` и инлайн-блок в `answer.build_answer`. Правка одного места не меняет продакшн-путь (CLI, golden, GUI идут через `build_answer`).
- Стемминг без отбрасывания служебных слов ухудшает поиск (проверено, Ф1.13:
  hit_at_5 0.679 → 0.643, doc_hit 1.000 → 0.857, ложный отказ на p25). Причина:
  AND-ветка требует ВСЕ токены вопроса, включая «какое», «сколько», «в»,
  которых на нужном листе нет. Стеммер помогает только вместе с
  (1) стоп-листом служебных слов, (2) пересортировкой OR по покрытию.
  Поодиночке любая из трёх правок даёт регресс.
Размазанность топа по изделиям — не признак неоднозначного вопроса. Проверено 09.11.2026 на 31 вопросе: правило «если в топ-20 фрагменты ≥2 изделий и второе ≥30% от первого — переспросить» даёт 12 ложных уточнений при требовании 0 (даже с порогом 50% — 9). Причина: в любом вопросе про двигатель или масло в топ попадают листы всех четырёх изделий — это свойство корпуса. Целевой кейс «ВСУ не запускается» правило тоже не ловит (в топе только Safir, АИ-9В в пуле отсутствует). Не повторять в такой форме.

## Метрики

- Метрика отказа двусоставная: сводный `refusal_false` смешивает ложные и обязательные отказы. Контроль ложных — только `refusal_false_on_found` (0.00), доля обязательных — `refusal_on_miss`. Отказ на промахе — корректное поведение, а не регресс.
- Константы `tests/test_golden_metrics.py` должны соответствовать числу вопросов (45: 16 explain / 11 fault / 18 procedure); правка набора без правки констант — красный тест.
- Эталоны аудируются до любых оптимизаций поиска. Урок Ф1.2: два дня настройки шли против части неверных эталонов, hit@5 0.214 → 0.643 без единой строки правок в поиске.
- В `questions.toml` — только точное имя файла из `docs/quality-candidates-*.csv` и **физические** номера страниц PDF, не печатные из колонтитула.
- Правки `questions.toml` — только агентом: ручное копирование уже привело к дублю `f11` и потере 11 записей.
- Промах без записи считается потерянным: если неверный ответ увидели и не
  нажали «Это не то» (журнал `feedback.jsonl`, Ф2.11), для проекта этого
  случая не было — он не попадёт ни в golden set, ни в диагностику. Живые
  вопросы инженера ценнее любых синтетических: их всего несколько за день,
  и каждый потерянный промах чинится вслепую.

## Код и контракты

- `_print_text` читает store (`is_continuation`): печать до `store.close()`, иначе `ProgrammingError: Cannot operate on a closed database` на ответе с парой соседних листов (исправлено в Ф1.3б.2, закреплено тестами).
- CLI-коды: `0` — ответ и все цитаты подтверждены, `1` — отказ или неподтверждено, `2` — ошибка среды, `3` — требуется уточнение (добавлен Ф1.4).
- `verify` считает лист существующим, если есть узел `sheet` ИЛИ непустая запись в `pages`.
- Классификатор `classify_answerability` вызывается после гейтов; при тестировании его контракта гейты изолировать (`monkeypatch ENABLED_GATES → ()`).
- `pages.text` и `pages_fts.body` — намеренно разные: в тексте дословный
  OCR, в индексе стеммированный и очищенный («двигателя» → «двигател»,
  вырезаны заполнители строк). Цитаты, сниппеты и verify берутся только
  из `pages.text`. Не выравнивать их друг под друга и не искать цитаты
  в индексе.

## Окружение Windows / PowerShell

- Кириллица в консоли отображается как cp866 — искажение отображения, не порча файла (файлы UTF-8).
- При копировании команд из Telegram в PowerShell к началу прилипает кириллическая «с» (получается `сcmd`) — команда не запускается; на таких строках PowerShell подвисает.
- `git show --output=` в PowerShell даёт пустой файл — захват вывода через Python subprocess; всегда `git --no-pager`.
- Долгие цепочки команд с `&&` в терминале Cline висят по 5 минут — выполнять по одной.
- Долговременная потеря сети к `max.km00.ru:8444` (прокси к модели) — это не ошибка проекта: правки в файлах целы, работа продолжается после восстановления.
