## Инструкция для владельца (дословно)

1. **Бэкап** (вы делаете сами, до запуска):
   ```
   copy "graph.db" "C:\PDF_Data\backups\graph.db.backup-20261106-f117-preemb"
   ```
   (путь — по правилу бэкапов; рабочая БД в корне проекта).

2. **Запуск пересчёта** (из корня проекта):
   ```
   venv\Scripts\python.exe -m pdfgraph emb-index graph.db --rebuild
   ```
   Не добавляйте `--chunk-size` — берутся дефолтные 600/120.

3. **Сколько ждать.** Замер скорости на реальных листах
   (`tmp_f117_speed.py`, выборка 40 листов): **18.7 чанков/с ≈ 13.1
   листов/с**; searchable-листов в корпусе 12 045 (замер командой из
   п. 5 до пересчёта) ≈ 16 500 чанков → **~15–18 минут** кодирования
   (оценка «час» из карточки — с запасом). Не прерывать процесс:
   `emb-index` пишет векторы постранично, повторный запуск идемпотентен
   (прерванный — просто перезапустить с `--rebuild`).

4. **Как понять, что процесс жив.** Промежуточного вывода у `emb-index`
   нет (отчёт печатается одним блоком в конце). Живость проверяйте по
   росту БД/сек:
   ```
   powershell -Command "while($true){(Get-Item graph.db).Length; Start-Sleep 30}"
   ```
   (в WAL-режиме рост видно по `graph.db-wal`; число растёт — процесс
   работает; стоящее число больше пары минут — завис).

5. **Как понять, что завершился и что всё посчитано.** Процесс печатает
   финальную строку и выходит с кодом 0:
   ```
   emb-index: chunks=~19500 embedded=13700 version=N continuation=K
   ```
   Контрольные проверки после:
   - маркер конфигурации и листы без векторов (ожидание: маркер
     `600:120:clean`, «без векторов 0» — у каждого searchable-листа есть
     чанки; пустые листы не считаются — их нет в searchable):
     ```
     venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'.'); from pdfgraph.store import Store; s=Store('graph.db'); sp=set(s.searchable_pages()); ep=set(s.embedded_pages()); print('emb_chunk=',s.get_meta('emb_chunk'),'version=',s.get_meta('emb_version'),'searchable=',len(sp),'embedded=',len(ep),'без векторов=',len(sp-ep)); s.close()"
     ```
     (таблица векторов — `page_embeddings`; ориентир в строке отчёта
     emb-index: `embedded=...` должен равняться числу searchable-листов).

6. **Чем проверять после.**
   - Позиция листа 38 в каналах по двум целевым вопросам:

     (скрипт замеряет лексику глубины 50/100/300/500/1000 и вектор
