# Ф2.1: веб-каркас — чат, /api/ask, PDF.js-открытие листа — отчёт

Дата: 02.11.2026. Карточка: работающий сервер, который спрашивает,
отвечает с цитатой и открывает PDF на нужном листе. Только чтение
функций поиска; query/rag_fusion/gates/verify/documents не тронуты.

## Запуск

`python -m pdfgraph.web --db graph.db` → http://127.0.0.1:8000;
порт — `PDFGRAPH_WEB_PORT` (по умолчанию 8000). Проверено на рабочей
базе: сервер поднят, страница открыта, PDF-эндпоинт отдал лист 38 кн. 7
(HTTP 200 в логе uvicorn).

## Замер зависимостей

`requirements-web.txt` (точные версии установлены в venv):
fastapi==0.162.0, uvicorn==0.54.0, jinja2==3.1.6, httpx==0.28.1.
PDF.js: **pdfjs-dist 3.11.174 (legacy build)** — pdf.min.js (377 КБ),
pdf.worker.min.js (1 133 КБ) лежат в `pdfgraph/web/static/pdfjs/`;
worker рядом с pdf.min.js (без него вьюер молча не рисует); в рантайме
обращений к CDN нет.

## Маршруты (pdfgraph/web/app.py)

- `GET /` — чат: три колонки (типы 212px / чат / просмотр 380px),
  переключатель типа слева; палитра и типографика — по утверждённому
  макету (#f2f4f6 фон, #ffffff панели, акцент #1f6f8b, радиус 6px,
  Segoe UI 15px/1.55, заголовки 11px caps 0.07em, моно для листов/кодов).
- `POST /api/ask` — только обёртка: build_answer + verify_citations +
  _evidence_rows; JSON: status (answer/refusal/clarify), exit_code
  (0/1/3), claims, citations (document, page, ok, system_code,
  doc_layer/doc_applicability/doc_revision, link, viewer_url),
  neighbors, applicability_warning, options. Ошибка среды → HTTP 500.
- `GET /doc/{document}/page/{page}` — FileResponse исходного PDF;
  папка — правило GUI (`--pdf-dir` > `PDFGRAPH_PDF_DIR` > DEFAULT),
  файл — `_find_pdf_file`; нет папки — 404 «папка с PDF не найдена,
  укажите PDFGRAPH_PDF_DIR», нет файла — 404 с именем. Факт: в самой
  базе путь к папке не хранится (meta содержит только schema/emb-ключи)
  — переиспользовано правило GUI по решению владельца.
- Лог: `web.log` рядом с базой — время, исход, вопрос.

## Три вида сообщений

Ответ — текст + цитаты с левой акцентной полосой и кликабельной
ссылкой (PDF.js-viewer в правой панели или новой вкладке); отказ —
причина, без кнопки открытия листа; уточнение — блок #fbf0dd с
кнопками вариантов (у варианта вторая строка — документ и раздел;
клик отправляет текст варианта новым вопросом — память диалога
(--context) в веб пока не подключена, отражено в «Не сделано»).

## Уроки прогона

- Jinja2-обработчик с нетипизированным `request` FastAPI считает
  query-параметром → 422; нужен `fastapi.Request`.
- Служебную строку «Фильтр по типу ВС» нельзя печатать в `--json`
  режиме — stdout должен остаться чистым JSON (урок Ф0.3в, повторился
  на веб-эндпоинте).
- В консоли браузера 404 на favicon.ico — косметика, не в карточке.

## Риски

- Store открывается на каждый запрос (просто и безопасно при
  конкурентных вопросах); при росте нагрузки — пул/один коннект с
  блокировкой (отдельная задача).
- `resolved_pdf_dir` фиксируется при старте приложения: смена
  PDFGRAPH_PDF_DIR требует перезапуска сервера.
