# Ф2.2: полноэкранный просмотр PDF — отчёт

Дата: 02.11.2026. Карточка: полноценный вьюер (масштаб, прокрутка,
поиск, поворот), миниатюра в правой панели, «Назад к ответу»,
офлайн. Поиск/ответ/гейты/verify не тронуты.

## Нумерация — главная проверка карточки

Формула (одна точка): граф-лист (0-based) + `PAGE_OFFSET = 1`
([`pdfgraph/gui/pdf_opener.py:32`](../../pdfgraph/gui/pdf_opener.py)) →
физическая страница вьюера. Маршрут `?view=full` подставляет
`#page=<граф-лист + 1>`.

Проверка на реальном документе (вопрос приёмки Ф2.1 «давление масла…»,
лист 38 — это **Двигатель ТВ3-117 078.00.5700 РЭ1 книга_1**, golden
p26/p27):

- физ. стр. 39 PDF содержит «**2.3.16**» — пункт 2.3.13 и далее
  (проверено извлечением текста PyMuPDF: физ. 38 — без пункта, 39 —
  «2.3.16 ЕСТЬ»);
- вьюер с `?view=full` открывает `#page=39` — инженер видит именно
  пункт 2.3.16; скриншот: `reports/web_f22_engine_page39.png` (вне git);
- автотест на смещение: `test_view_full_renders_shell_with_offset`
  проверяет `const PAGE = 39` для граф-листа 38.

Замечание по формулировке карточки: «лист 38» в приёмке Ф2.1 — лист
книги 1 РЭ1 двигателя (golden), а не кн. 7; предварительная проверка
кн. 7/38 показала техкарту 022.10.00 «Стр. 213», строки «2.3.16» в
текстовом слое кн. 7 нет ни на одной из 810 страниц — зафиксировано,
не подгонялось.

## Реализация

- Официальный вьюер `web/viewer` из npm-пакета собрать не удалось:
  npm-тарбол содержит только `pdf_viewer.css/js` без HTML-оболочки,
  релизный zip GitHub на этой машине недоступен по SSL; исходный
  `viewer.html` из репозитория тянет es-module-shims/importmap — сборка
  хрупкая. Решение: собственный полноэкранный вьюер на API pdf.js
  3.11.174 (`static/pdfjs/full_view.html` логика в
  `templates/full_view.html`): непрерывная прокрутка всех листов с
  ленивым рендером окна ±2/±3, масштаб ×0.5–×4 (кнопки), поворот 90°,
  **поиск по тексту** (getTextContent по всем листам, список
  страниц-совпадений, переход к первой) — русские подписи. Ограничение:
  подсветки вхождений внутри страницы нет, поиск ведёт на лист —
  задокументировано как ограничение каркаса.
- Маршрут `GET /doc/{document}/page/{N}`: с `view=full` — HTML-оболочка
  (`templates/full_view.html`, кнопка «Назад к ответу» = history.back()
  с fallback на `/`), без параметра — сырой PDF (регресс-тест Ф2.1).
- Фронтенд ([`pdfgraph/web/static/app.js`](../../pdfgraph/web/static/app.js)):
  «Открыть лист →» и клик по номеру листа открывают `?view=full` в
  новой вкладке; правая панель сужена до 270px (решение владельца),
  показывает миниатюру цитируемого листа (рендер pdf.js) и кнопку
  «Открыть на весь экран»; последняя переписка хранится в
  sessionStorage — «Назад к ответу» возвращает чат с тем же вопросом,
  браузерный Back не выкидывает на голый PDF (вьюер открывается в новой
  вкладке, история вкладки чистая).

## Тесты (tests/test_web_f22.py, 4; полный прогон 469 passed)

1. `view=full` — оболочка, «Назад к ответу», `#page=39` для листа 38
   (смещение), сырой URL без view-параметра;
2. регресс: без `view=full` — application/pdf, %PDF;
3. офлайн: в оболочке нет внешних URL;
4. цитата несёт `full_url` (?view=full).

## Не сделано и почему

- Подсветка вхождений поиска внутри страницы — ограничение каркаса
  (переход на лист есть); отдельная карточка при необходимости.
- favicon 404 в консоли браузера — косметика из Ф2.1.

## Риски

- Ленивый рендер окна ±2/±3 при длинных документах (810 листов) —
  скачок на далёкий лист рендерит окно с задержкой; приемлемо.
- pdf.js стримит PDF запросами 206 Partial Content — FileResponse
  поддерживает Range (подтверждено логом сервера).
