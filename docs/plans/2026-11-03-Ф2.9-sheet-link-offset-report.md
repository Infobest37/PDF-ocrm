# Ф2.9. Ссылка на лист из карточки — единая точка смещения — отчёт

Дата: 2026-11-03. Базовая линия: коммит 8ae72f4 (2.8).

## Решение владельца (в ходе карточки)

Семантика маршрута `?view=full` НЕ меняется: внутри ссылки остаётся
граф-лист (page/372), сервер по-прежнему прибавляет PAGE_OFFSET; кнопку
открытия подписываем физической страницей — «Открыть лист — стр. 373»
при адресе page/372. Причина: смена семантики сделала бы
недействительными все уже существующие ссылки (логи, отчёты, закладки).

## Файлы изменены

- `pdfgraph/web/app.py` — новая :func:`sheet_links(document, page)` —
  единая точка сборки всех ссылок на PDF: `link` (граф-лист, сырой PDF),
  `full_url` (граф-лист + `?view=full`), `viewer_url` (PDF.js-viewer с
  физической страницей), `physical_page` (graph + PAGE_OFFSET; единый
  источник смещения — `pdfgraph.gui.pdf_opener`, как и было). Через неё
  строятся: цитаты (`_citation_rows`, + `physical_page` в payload),
  листы карточек техкарт (обогащение payload), соседние листы (раньше
  ссылок не имели вовсе). Маршрут `?view=full` не тронут (контракт Ф2.2:
  GET /page/38?view=full → PAGE=39 — тесты не менялись).
- `pdfgraph/techcard_card.py` — `CardSheet.part`: метка многолистовой
  карты «начало карты»/«продолжение» (ставится, только когда
  продолжение есть); приклейка продолжений без повторённого номера —
  признак :meth:`store.is_continuation` (текст «Продолжение»), лист с
  любой другой картой той же базы и лист, занятый другой карточкой
  ответа, не приклеиваются. `build_card` сохраняет `part` (листы-
  продолжения идут без собственного фрагмента, с сырой ролью родителя).
- `pdfgraph/cli.py` — метка листа печатается в блоке карточки
  аддитивно: «… — как выполняется (продолжение)».
- `pdfgraph/web/static/app.js` — кнопка карточки: подпись
  «Открыть лист — стр. {physical_page}», адрес — `full_url` из payload
  (ручная сборка ссылки удалена); строка листа дополняется меткой
  `part`; соседние листы — кликабельные ссылки (та же `full_url`);
  миниатюра рендерит `physical_page` (дубль «+1» в JS удалён).
- `pdfgraph/web/templates/full_view.html` — точный переход: текущая
  страница и прыжок считаются по фактической геометрии отрисованных
  canvas (`offsetTop`), а не по шагу 1200px. Прежняя аппроксимация и
  была причиной «страницы на единицу раньше»: высота листа зависит от
  масштаба и документа, (N−1)·1200 попадал в слот предыдущего листа.
  Затронуты `currentPage()`/`updatePosition()`/`jumpTo()` и обработчики
  масштаба/поворота (центр запоминается до сброса canvas).
- `tests/test_web_f22.py` — +4 теста; `tests/test_techcard_card_f25.py` — +3 теста (перечень ниже).

## Не сделано и почему

- Сквозная браузерная проверка клика на реальном PDF не выполнялась
  (автотесты покрывают payload и маршрут; геометрия canvas — чистый JS
  без тестового контура). Проверка «страница с шапкой карты» — вручную
  владельцем на рабочей базе.
- Соседние листы в GUI (Qt) остаются текстом без ссылок — открытие в GUI
  идёт двойным кликом через `open_pdf_at_page` (смещение там уже
  применяется); карточка Ф2.9 про web-ссылки.

## Замечено попутно, не правил

- `viewer.html` (embedded PDF.js) не проверялся на смещение — цитаты
  используют его через `viewer_url` с физической страницей, изменений
  не требовал.
- В `_with_continuations` приклейка ограничена признаками карточки;
  цепочки длиннее двух листов поддерживаются (цикл идёт до первого
  занятого/непомеченного листа).

## Риски

- Приклейка продолжения без номера опирается на флаг `is_continuation`:
  если OCR не распознал «Продолжение табл.» на листе-продолжении, лист
  не приклеится (прежнее поведение).
- Подпись кнопки берёт `physical_page` из payload; при старом кэше
  app.js без нового сервера подпись не отрисуется (адрес сохранится) —
  обновлять файлы парой.
