# Ф2.3: ответ по-человечески — чистка лида и выбор предложений — отчёт

Дата: 02.11.2026. Карточка: текст над цитатой собирается из листа
(чистка шапок/колонтитулов + до 3 предложений по покрытию значимых слов
вопроса); цитата и verify не тронуты — `Claim.text` остаётся дословным
сниппетом, человеческий абзац кладётся в `Claim.answer_text`
(существующее поле, verify проверяет `text`).

## Реализация

- [`pdfgraph/humanize.py`](../../pdfgraph/humanize.py) (новый):
  `is_header_line` (порог 25 символов с исключениями — заголовки с
  нумерацией «1.1.», «Раздел/Глава/Рис./Табл./Таблица/Приложение» и
  короткие строки со значимым словом вопроса, оба исключения — решение
  владельца; «Стр. N», «Авг 13/13», коды, шапки-фразы, OCR-мусор),
  колонтитулы по первым двум строкам (сэмпл 30 листов документа),
  `select_sentences` (термины — `gates.question_terms`, порог ≥2
  покрытых термина для вопросов с ≥2 терминами — одно совпадение
  шум, урок прогона), `lead_paragraph` (fallback — первый
  содержательный абзац).
- [`pdfgraph/answer.py`](../../pdfgraph/answer.py): в обёртке
  `build_answer` для не-отказа первый claim получает `answer_text`.
- [`pdfgraph/cli.py`](../../pdfgraph/cli.py): в «Ответ:» абзац печатается
  над цитатами; в JSON `answer_text` аддитивно. GUI
  ([`pdfgraph/gui/viewmodel.py:62`](../../pdfgraph/gui/viewmodel.py))
  уже брал `answer_text` — правки не потребовалось. Веб отдаёт
  `answer_text` с Ф2.1.
- Уроки прогона (на реальном листе 38 РЭ1 кн. 1 — пункты 2.3.13–2.3.24
  в одной строке БД): точечные лидеры оглавления OCR превратил в
  цепочки «........нннннннннннн» ВНУТРИ строки между параметром и
  значением. Решение: вырезание лидеров (`……` ≥6 точек и пробеги ≥10
  символов из ≤3 уникальных букв без пробелов → « ») и приоритет
  OCR-правил над «спасением вопросным словом» (мусор вклеен в одну
  строку со словами вопроса). Порог покрытия ≥2 отсёк шумовое
  «Температура масла на входе…» (1 термин) при вопросе про давление.

## Не сделано и почему

- Подсветка абзаца как «фрагмент листа» при fallback — флаг
  возвращается (`lead_paragraph`), отображение пометки не добавлено в
  cli/веб (одна строка в каждой, при необходимости — за 5 минут).
- Поиск «трещотка не держит» возвращает лидера из содержания каталога
  дефектов — это ранжирование (Ф1-карточки), не тронуто.
- Сабворд-флексии («масло»≠«масла») не матчатся — substring-правило
  Ф1.3а, изменение стемминга вне карточки.

## Риски

- Порог ≥2 термина может дать fallback на страницах, где вопрос
  встречается одним словом — там показывается первый содержательный
  абзац (честно помечен флагом).
- Чистка не знает вёрстки: длинные шапки (>25 символов без маркеров)
  останутся.
