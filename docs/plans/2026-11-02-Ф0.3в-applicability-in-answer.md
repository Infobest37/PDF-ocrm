# Ф0.3в: слои и применимость в ответе и в поиске — отчёт

Дата: 02.11.2026. Карточка: фильтр типа во всех ветвях поиска, пометки
документа в цитатах, предупреждение о чужом борте, честный отказ для
борта без документации. Ранжирование, веса, гейты, verify не тронуты.

## Замер перед включением фильтра (решение владельца Ф0.3в)

`SELECT COUNT(*) FROM pages WHERE aircraft_type IS NULL OR aircraft_type = ''`
→ **0 из 13 700**; все листы Ми-8МТВ. Фильтр безопасен: простановка
меток и бэкап не потребовались, листов с проставленной меткой — 0.

## Что сделано

- [`pdfgraph/query.py`](../../pdfgraph/query.py): `vector_search(...,
  aircraft_type=None)` — при заданном типе канал отсекает листы других
  типов (пустые метки при заданном фильтре тоже отсекаются — решение
  владельца); `hybrid_search` пробрасывает параметр. Лексические ветви
  (код, партномер, FTS, триграмма) фильтровали тип и раньше — тесты
  закрепили каждую.
- [`pdfgraph/answer.py`](../../pdfgraph/answer.py): поле
  `Answer.applicability_warning`; `applicability_verdict(store,
  question, fragments)` — (отказ, предупреждение) по борту вопроса:
  - п. 4: борт в формате 2xxxxx (правило Ф0.3а), в documents нет ни
    scope=all, ни scope=serials с этим бортом → ранний отказ
    «документации по борту N в базе нет» (цитат нет, код CLI 1);
  - п. 3: борт есть, лидер — scope=serials без этого борта, но отказ
    не сработал (есть базовые/подходящие) → ответ с пометкой
    «документ применим к бортам …; ваш борт не указан»;
  - без борта в вопросе или без таблицы documents — прежнее поведение;
    отсутствие таблицы (в т.ч. Mock-фикстуры тестов) не глушится
    молча — logger.warning.
- [`pdfgraph/cli.py`](../../pdfgraph/cli.py): `--type` получил алиас
  `--aircraft-type`; без значения — текущий тип базы (единственный
  непустой `DISTINCT aircraft_type` из pages; несколько/ни одного —
  фильтр не ставится; решение печатается только в текстовом режиме —
  stdout в `--json` остаётся чистым JSON); `_evidence_rows`
  дополняет каждую цитату полями `doc_layer`, `doc_applicability`,
  `doc_revision` (аддитивно; пусто, если строки нет); текстовый вывод
  доказательств печатает «— слой …, применимость …, ревизия …»; JSON
  получает `applicability_warning` при непустой пометке.

  — без изменений (байт-в-байт поведение без борта в вопросе; в базе
  один тип, фильтр Метки не меняет).
- Отказ на борт без документации — код 1, цитат нет (тест +
  отказ-ветка в build_answer).
- Пометки видны в тексте и в JSON (тест `test_doc_fields_in_evidence`,
  JSON-ключи в citations каждого claim).

## Не сделано и почему

- Путь `rag_search` (use_rag_fusion=True, по умолчанию выключен)
  остался без типа-фильтра — `pdfgraph/rag_fusion.py` трогать
  запрещено карточкой; включение фильтра там — при включении самого
  rag-fusion.
- GUI не печатает `applicability_warning` и doc-поля — отдельная
  карточка GUI при необходимости (данные уже в Answer).
- `doc_revision` показывает ревизию из documents (revision_no/date);
  supersedes-связь в пометку не включена — не требовалась карточкой.

## Риски

- Фильтр вектора по `pages.aircraft_type` — один запрос на вызов
  `vector_search`; при многотипной базе множество листов типа
  кэшировать не стал (корректность важнее; замер латентности не
  показал сдвига).
- Отказ по борту срабатывает до гейтов конкретики: вопрос «борт 27777»
  в базе без подходящих serials и без базовых получит бор-отказ, а не
  гейт-отказ — это и есть п. 4 карточки.
