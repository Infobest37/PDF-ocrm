## Решения владельца в ходе задачи

- Кнопка обратной связи под всеми тремя исходами, подписи по исходу:
  answer → «Это не то», refusal → «Ответ в документах есть»,
  clarify → «Вопрос был понятен» (у refusal/clarify sheets пустой).

## Приёмка (по пунктам карточки)

- «Это не то» → запись в feedback.jsonl со всеми полями (ts, question,
  status, sheets, top_documents, correct_sheet, comment) — тест
  `test_feedback_write_all_fields`.
- feedback-list показывает сводку; `--json` — словарём — тесты
  `test_feedback_list_text_summary`, `test_feedback_list_json`.
- Искусственная ошибка маршрута (RuntimeError в ask_fn) → строка в
  errors.log с `route=/api/ask`, вопросом и типом/текстом ошибки;
  следующий запрос жив (200) — `test_unhandled_error_logged_and_server_alive`.
- Поиск, выдача, метрики не изменились — существующие тесты зелёные.

## Не сделано и почему

- Кнопка в GUI (Qt) не добавлялась — карточка говорит о вебе и CLI
  (CLI показывает строки, веб — кнопкой).
- Экспорт журнала и повторная отправка «Отмечено» — за рамками карточки.

## Замечено попутно, не правил

- feedback.jsonl/errors.log не ротируются — при большом потоке записей
  файл растёт; кандидат на отдельную карточку.

## Риски

- Параллельные POST /api/feedback пишут append-ом; на Windows
  одновременная запись двух процессов может перемешать строки
  (журнал технический, единственный инженер-пользователь — риск низкий).
