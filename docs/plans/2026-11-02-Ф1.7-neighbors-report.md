# Ф1.7: окно соседних листов в выдаче — отчёт

Дата: 02.11.2026. Карточка: добавить к топ-5 выдачи окно соседних листов
(−1/+1 того же документа) отдельным списком ссылок, не меняя ранжирование;
новая метрика `hit_at_5_with_neighbors`, старая `hit_at_5` не переопределяется.

## 1. Почему `expand_continuations` не работал на e09 и e18 (текст, не правка)

- Замер на рабочей базе (read-only SQL): `SELECT COUNT(*) FROM pages WHERE
  is_continuation = 1` → **0**. Флаг не проставлен ни на одном листе:
  build его не заполняет, ставится только вручную
  (`pdfgraph/store.py::set_page_continuation`).
- Механика [`pdfgraph/query.py::expand_continuations`](../../pdfgraph/query.py):
  она проверяет флаг `is_continuation` **найденного** листа и добавляет
  только **предыдущий** лист (хвост «Продолжение табл.»). На e09 и e18
  флаги пустые → ветка никогда не срабатывает. Окно «только внутри листа»
  ни при чём: сниппет и так режется из текста одного листа.
- Вывод: соседство по флагу на этой базе мертво; карточка Ф1.7 вводит
  соседство по позиции (−1/+1), флаги `is_continuation` не тронуты —
  механика остаётся для честных продолжений таблиц, если владелец
  расставит флаги вручную.

## 2. Что сделано

- [`pdfgraph/answer.py`](../../pdfgraph/answer.py):
  - поле `Answer.neighbors` — список `{"document", "page", "label"}`;
  - `collect_neighbors`: для каждого фрагмента топ-5 — листы −1 («предыдущий
    лист») и +1 («следующий лист, возможно продолжение»); максимум 2 на
    фрагмент; дубликаты не повторяются; листы `needs_rescan`/`is_service`
    не берутся; границы документа соблюдаются проверкой существования
    строки листа (у первого/последнего листа соседа с той стороны нет);
  - дедупликация — против топ-5 и уже добавленных соседей. Кейс e18:
    ожидаемый лист 23 стоит в выдаче на ранге 6–10 — соседом от топ-5 он
    остаётся (замер Ф1.6/H1 закрывал e18 именно так); от глубокой части
    выдачи дубли не исключаются;
  - флаг `PDFGRAPH_NEIGHBORS` (читается при каждом вызове, образец —
    `SPECIFICITY_WEIGHT_ENV`): по умолчанию включён, `0`/`false`
    отключает — `neighbors == []`, выдача байт-в-байт прежняя;
  - `build_answer` стал обёрткой над `_build_answer_core`: контракт
    (сигнатура, возврат) прежний, после построения ответа добавляется
    окно соседей. Ранжирование, слияние, гейты, verify не тронуты.
- [`pdfgraph/cli.py`](../../pdfgraph/cli.py): в JSON — ключ `neighbors`
  (только когда соседи есть и ответ не отказ); в тексте — блок
  «Соседние листы (может быть продолжение):» после доказательств; при
  отказе блок не печатается. Соседи не попадают в claims/citations.
- [`tests/golden/metrics.py`](../../tests/golden/metrics.py): в строку
  вопроса — `hit_at_5_with_neighbors` и `neighbors`; в сводку — метрика
  `hit_at_5_with_neighbors` рядом с `hit_at_5`; колонка в таблице.
- [`tests/test_neighbors_f17.py`](../../tests/test_neighbors_f17.py) —
  10 тестов (TDD: 8 из 9 первых падали без правки; `test_flagged_
  neighbors_excluded` проходил тривиально, пока поля `neighbors` не
  существовало, — отмечено честно; десятый тест на кейс e18 добавлен
  при разборе золотого прогона и падал до правки дедупликации).
- [`tests/test_golden_metrics.py`](../../tests/test_golden_metrics.py):
  `PLANNED_METRICS` дополнен `hit_at_5_with_neighbors` (метрика
  обязательна к проверке в отчёте — правка требуется карточкой).

## 5. Не сделано и почему

- `is_continuation` не заполняется и `expand_continuations` не правился —
  вне карточки (правка флагов — решение владельца, ручной CLI есть).
- Соседи не добавляются к rag-fusion пути (`use_rag_fusion=True`) —
  обёртка `build_answer` покрывает и его; отдельной приёмки этого пути
  не было, в golden он не используется.

## 6. Замечено попутно, не правил

- Сниппеты соседей не выводятся вовсе (только ссылка и подпись) — по
  карточке; если владельцу нужен текст соседа, отдельная карточка.
- Латентность золотого прогона плавает (1045→1192 мс) — прогрев/машина,
  не связано с правкой (соседи не ищут текст, только строки pages).

## 7. Риски

- Сосед может дублировать лист из глубокой части выдачи (кейс e18) —
  в тексте он появится дважды: как фрагмент ранга 6–10 (не печатается)
  и как сосед; в JSON оба списка разделены.
- Флаг по умолчанию включён: потребители `Answer` получают новое
  непустое поле; GUI читает `answer.clarification`/`refusal` — поле
  добавочное, обратная совместимость сохранена (дефолт `field(default_factory=list)`).
