# План: система «как NotebookLM» для компании (на базе pdfgraph)

Дата: 2026-10-28. Статус кода: master, коммит `083ea9c`. Код в этом плане **не меняется** —
это руководство к действию. При выполнении пунктов, требующих правок, заводится
отдельная задача по правилам AGENTS.md.

## Что уже есть (сверка с фактическим кодом)

| Возможность NotebookLM | Состояние в проекте |
|---|---|
| Загрузка документов | Есть: окно сборки (builder) — выбираешь папку с PDF, запускается OCR |
| Ответы строго по документам | Есть, строже NotebookLM: цитаты проверяются машинно, неподтверждённое — явный отказ |
| Прямая ссылка на страницу | **Уже реализовано** (Stage D): клик по цитате в чате открывает PDF в Acrobat/Edge на нужной странице (`pdfgraph/gui/pdf_opener.py`) |
| Уточняющие вопросы | Уже есть: вариантные уточнения (до 2 раундов), исправление «Не то: …» (`pdfgraph/conversation.py`) |
| ИИ-модель «для беседы» | Уже есть: синтез ответов через настройки ИИ (ключ, сервер, модель) — `pdfgraph/gui/settings.py`, `pdfgraph/rag_fusion.py`; работает и без сети (экстрактивный режим) |
| Обновление документа | Частично: замена листов перескана (`pdfprepare/replace.py`); пересборка графа идемпотентна |
| Переносимость | Есть: портативная сборка `dist/pdfgraph/` (2 exe + Tesseract), ярлык |

## Чего не хватает для компании

1. Реестр типов ВС (в коде фактически один тип Ми-8МТВ; фильтр по типу существует, списка типов нет).
2. «Библиотека документов»: замена целого документа на новую редакцию одним действием, история версий.
3. Общий доступ для сотрудников: где хранить graph.db и PDF, кто пересобирает граф.
4. Ручная приёмка на реальном рабочем месте (ярлык → вопрос → вердикт → ссылка на страницу).

## Шаги

### Шаг 0. Приёмка текущего состояния (без кода, 1 час)
- [ ] Запустить ярлык «Граф знаний», задать вопрос по Ми-8МТВ.
- [ ] Кликнуть по цитате → PDF открывается на нужной странице.
- [ ] Прогнать тесты: `venv\Scripts\python.exe -m pytest -q` (базовая линия ~133+).

### Шаг 1. Навести порядок в библиотеке документов (без кода, самое важное)
- [ ] Единая структура: `Библиотека\<Тип ВС>\<PDF документов>`.
- [ ] Правило имён: только имя документа, без дат/пометок «новая редакция».
- [ ] Вести реестр документов (таблица Excel): тип ВС, код документа, редакция, дата изменения, кто заменил.

### Шаг 2. Подключить ИИ-модель (настройка, без кода)
- [ ] Выбрать: локальная модель (Ollama) в офисе ИЛИ облачный провайдер с совместимым API.
- [ ] В окне «Настройки» программы ввести адрес сервера, ключ, модель; проверить «Test Connection».
- [ ] Включить галочку «LLM-ответ (синтез)» — она активируется только после ввода ключа; при желании «Умный поиск (RAG-Fusion)».
- [ ] Проверить качество на 10–20 реальных вопросах инженеров; убедиться, что отказ при неуверенности устроит пользователей.
- [ ] Диагностика 28.10.2026: уточняющие вопросы и «диалог» работают ТОЛЬКО при
      включённом синтезе с непустым ключом — классификатор, возвращающий
      «задать уточнение», вызывается только в ветке синтеза
      (`pdfgraph/answer.py`, `synthesis_enabled` → `classify_answerability`).
      Без ключа галочка «LLM-ответ (синтез)» заблокирована
      (`pdfgraph/gui/app.py`: `setEnabled(api_key.strip())`), срабатывающих уточнений нет вообще.
      Проверка: задать двусмысленный вопрос («давление», «радиомаяк») → должны
      появиться варианты A/B/C с цитатами; ответить «A» или «Не то: <уточнение>».
      Макс. 2 раунда уточнений на вопрос. Свободной «беседы» (как NotebookLM
      на любую реплику) в коде пока не предусмотрено — см. Шаг 5.

### Шаг 3. Полный комплект по типу ВС (без кода)
- [ ] Прогнать все PDF типа через builder → изучить .report.txt о пересканах.
- [ ] Пересканами заменить плохие листы, пересобрать.
- Диагностика 28.10.2026 (по построенному графу, 13 701 лист / 49 документов):
  отчёты pdfprepare пометили только 12 листов, а полный скан текстов нашёл
  517 проблемных (185 «мусорные строки», 326 низкое качество, 6 битая
  кодировка/цифры без текста). Мусор сосредоточен в каталогах деталей/дефектов
  и РЭ агрегатов; основные РЭ почти чистые. Список: `docs/rescan-list-2026-10-28.csv`
  (физический лист = номер в графе + 1), сводка и приоритеты:
  `docs/rescan-list-2026-10-28.md`. Особые случаи: листы 363–364
  «Двигатель ТВ3-117 РЭ1 кн.1» — битая кодировка (поиск по кириллице не работает);
  дубль «РТЭ кн.7» под двумя именами даёт двойные попадания (см. Шаг 1).
  Эксперимент 28.10.2026 (без перескана): psm 3/11 частично спасают текстовые
  страницы (КД.Д-1701 psm 11: 30→40 чисел; л.9 Каталога дефектов psm 3 вытащил
  заголовок части), страницы-фото (ВР-14 л.120, Каталог дефектов л.128) не
  лечатся ничем — только фильтр из выдачи; битая кодировка л.363 book_1
  чинится полным latin‑1→cp1251 («ТВ3-117 РУКОВОДСТВО…») — правка в конвейер.
