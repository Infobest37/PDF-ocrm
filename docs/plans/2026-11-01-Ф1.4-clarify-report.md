## 2. Первый прогон полигона (форма) → решение владельца

Формульный слой (маркеры «как», «почему», «сколько», однородность выдачи) не отделил неполные слотless-вопросы от корпусных вопрос-действий: у обоих классов слоты пусты, гейты неприменимы, однородность пересекается (корпусные группы 3–8, полигонные 1–7). Владелец (Ф1.4.1, вариант B): **clarify — только на провале гейтов конкретики** (в вопросе есть число/обозначение, его нет на листе-лидере, а тема найдена); слотless-вопросы — только answer/refuse, как раньше; форма вопроса не отличает полный от неполного. Уточнение по смыслу — задача слоя с моделью (кандидат — опциональный «модель-верификатор», решение владельца отдельно).

## 4. Метрики отказа (золотой прогон, `reports/golden_run.json`, свежий)

- **refusal_on_miss = 0.100** (n=10; отказан e04, e06 → clarify) — **новый baseline, принят решением владельца**. Прежний 0.200 (отказы e04+e06) относился к конфигурации Ф1.3б, где уточнений не было: перевод e06 из отказа в clarify обязан опустить метрику до 1/10 — это арифметика, не регресс.
- Пояснение метрики: refusal_on_miss считает только отказы; уточнение на промахе — тоже корректное поведение (лишнего листа не выдано). Суммарно на 2 из 10 промахов система не выдала лишний лист: один отказ (e04) и одно уточнение (e06).
- Контроль ложных отказов не изменился: **refusal_false_on_found = 0.000** (требование 0.00).
- Сопутствующие цифры (как есть): hit_at_5 **0.643** (n=28), citation_precision **1.000**, doc_hit_at_5 1.000; refusal_recall на полигоне Ф1.3б — 0.70 (документированный потолок детерминированных гейтов, не пересчитывался).
- Пин-тестов на 0.200 нет; `golden_run.json` в git не входит.
