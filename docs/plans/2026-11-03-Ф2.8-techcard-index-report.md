## Не сделано и почему

- Подстрочный индекс «₂» (OCR даёт «у»: «033.30.00 ay», «by») не
  распознаётся: карточка Ф2.8 ограничена одной цифрой 1; правка без
  отдельного решения владельца.
- Заголовочная зона для «;»/«:» — окно ±6 строк: ссылка «см. карту … а;»
  на листе, где шапка карты есть в пределах окна, будет засчитана а1
  (в корпусе такие ссылки не найдены — замер ДО правки: 13 вхождений
  рядом со ссылочными словами, все в таблицах РО с шапкой).
- Поле applicability не печатается при отказе/уточнении — карточки там
  не строятся (прежнее поведение Ф2.5).

## Замечено попутно, не правил

- Индекс OCR даёт и как «:» («024.20.00 а:», «024.40.00 а:») — включён в
  те же правила, что и «;» (заголовочный гейт), наравне с одобренными
  владельцем «1»/«;»/«₁».
- Запись «033.40.00ь1» — OCR буквы «ь» вне таблицы двойников; канонизация
  неизвестных букв не добавлялась (риск ложных карт).
- В `_search_techcard` остаётся недостижимый `return section` после
  `return cards + section` (старый артефакт Ф1.9б) — не рефакторил.
- Заголовок карточки а1 на реальном л.132 обрезается OCR-вёрсткой
  («Осмотр светотехнического» без «оборудования») — поведение Ф2.5,
  не карточка Ф2.8.

## Риски

- Ссылочная «;» в пределах ±6 строк от шапки на реальном листе даст
  ложную карту а1 (в корпусе не обнаружено, контроль — замер ДО правки).
- Сужение базового поиска: запрос «…а» больше не находит листы «…а1»
  (цель карточки); если инженер ищет базу по дополнению — нужен запрос
  «…а1».
- `_techcard_matches` теперь читает page_text каждого кандидата FTS —
  на раздел-запросах чуть больше чтений; золотая латентность без
  изменений (1085 мс медиана).
