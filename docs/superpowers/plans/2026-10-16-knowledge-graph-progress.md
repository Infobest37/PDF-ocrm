## Принятые решения (не пересматривать молча)

1. **Инвариант цитат** — `snippet` берётся из оригинального текста листа, смещения
   в него же, `page_text[старт:конец] == snippet` гарантируется конструкцией и
   тестом. Это основа запрета на выдумки — задача 2.5 обязана строиться на нём.
2. **Шаблон обозначения детали** — `_looks_like_part_number` в `pdfgraph/build.py`:
   только `[0-9A-ZА-ЯЁ.-]`, есть точка, есть буква ИЛИ начало из пяти+ цифр, длина
   ≥6. Отсекает `КОЛИЧ. НА ЕД. СБ.`, `960-2. ® A OOO ®`, `1.`, `3`; сохраняет
   `8МТ.6101.100`, `869309.001-03`, `8МЁ.7226.000`.
3. **Схема рёбер:** `contained_in` — от ребёнка к родителю (`sheet→subsystem`,
   `subsystem→system`, `system→type`); `documented_on` — `document→sheet`;
   `has_part`/`has_figure` — `sheet→part`/`sheet→figure`; `references_system`/
   `references_figure` — `sheet→system`/`sheet→figure`. Ненайденные цели — узел
   `pending_reference`.
4. **Поиск:** сначала AND по всем токенам, при пустом результате — OR с
   `score × 0.8`. Оценка: код/деталь = 1.0, текст = `1/(1+|bm25|)`.
5. **Нормализация** (`ё/е`, регистр, тире) применяется к поисковому индексу, а не
   к `raw`-тексту — анти-цель проекта «не искажать документ».
6. **Ответы на этой итерации — экстрактивные** (цитаты без пересказа модели);
   подключение LLM — отдельная задача через интерфейс `Answerer` с обязательной
   проверкой цитат.
7. Пустой лист — граница раздела, не дефект; в отчёт о пересканировании не попадает.
